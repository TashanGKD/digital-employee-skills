# 已有对话投递与原生队列

先发现宿主当前提供的查找、读回、队列、等待工具，并读真实schema。以下是所需语义，不承诺某个宿主版本一定暴露同名工具；本包不实现Codex服务端或私有socket代理。

## 普通交办

确定真实目标线程、工作区、来源、完整结果、可自行判断部分、必要资源和交付处。使用明确queue-only的现有接口，例如部署已验证的thread/queue/add；不能仅凭send_message名称或“忙完再看”的正文判断它不打断。没有队列语义时不要擅自升级steer或interrupt。

保存稳定client/request ID、定稿全文SHA和实际回执。只有threadId只能说已提交；queueId或队列读回才证排队；原回合精确输入证投递；对方原笔记/实际动作证接手；产物和交付回执另验。队列快速变空先查自动消费，不再发一份。

## 合并与收口

同一原事项进展、补充和结果按接收方需要合并。未消费项可经已验证的queue update更新同一ID，已进回合的输入不改。已完成或重复项先保存全文、原ID、依据和当前结论，再由官方队列接口收口；不删历史或取消原业务。真正未完仍保留。普通核收不逐条回“收到”，也不要求两边互等确认。

附带的scripts/queue_closeout.mjs是可注入已验证调用器的库：默认dry-run、不连接宿主。applyPlan(plan,{call,archiveDir,execute})只处理人工/员工已经逐项复核的merge/retire计划，不自动分类。执行需新建独占archiveDir，检查原输入SHA后才改；未知先核原单。它不提供RPC客户端。宿主字段变化须先适配实际合同，不照抄旧私有socket。

库使用的部署合同：list返回data数组和可选nextCursor；行具有id/input；update/delete用threadId及queuedSubmissionId。只有你的实际宿主经核对满足此合同才能接入；测试使用隔离mock，不证明真实投递。

## 故障

已受理或结果未知先核原ID/定稿。入口失败保存原请求，查当前正常恢复，不改低层队列表、不新建聊天、不另发副本。对方明确撤销在途业务时沿真实取消/修订能力处理，不把异常当作随意打断许可。
