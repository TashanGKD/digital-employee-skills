# 员工工作入口

已承接的事按原完成条件办到实际产物/答复、交付证据和工作本更新；有问题先自行排障并继续能做的部分，确实受阻时留责任人和恢复条件。无已承接任务可以按岗位约定等待，不凭空制造工作。工作方式和任务进度分别沿共同Skill，不替换旧字段或恢复本人暂停的动作。

这里是本岗位的独立工作资料区。原对话与项目执行目录见STATE.json（`STATE.json`）的identity；项目适用指引和已有授权继续生效，目录独立不扩展权限。

## 从哪里接续

1. 按需查用共同数字员工Skill（`{{skill_entry}}`），共同默认和可选模式只在该Skill维护，不在本目录再抄一份。
2. 读ROLE.md（`ROLE.md`），恢复本岗目的、职责关系、授权、共享真源和长期约定。
3. 读CURRENT.md（`CURRENT.md`）及相关原笔记；尚无总览时先看workbook中是否已有真实工作，空目录不代表遗漏或已完成。
4. 需要渠道身份、原读取位置、系统接入或发件事实时，按STATE.json（`STATE.json`）的指针查真实记录。经验与原件只按当前问题取用。

## 内容放在哪里

- 岗位事实与长期约定：ROLE；不要在本文件维护第二份。
- 逐件目标、判断、状态、下一步和过程：原workbook笔记；CURRENT由生成器产生。
- 岗位级重要变化及原因：JOURNAL.md（`JOURNAL.md`）；不重复逐件流水。
- 有条件的经验：experience按需建立，业务状态仍回原笔记。
- 共享项目代码、业务表和正式资料：沿ROLE指明的原位置，避免复制成第二个真源；协商共享文件的编辑责任。

小时接续和已授权群@由统一系统登记、维护与核验，本岗只留真实回执指针，不建监听器、不改调度私有存储、不填监控报表。旧记录与成功回执保留，未知先查原请求。
