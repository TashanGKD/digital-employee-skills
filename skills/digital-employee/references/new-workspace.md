# 新员工资料区：独立记录，共用项目，旧岗兼容

用户在2026-10-31确认的新建默认。用于第一次建立员工资料区；已有员工先不迁移、不改字段名、不重写历史，继续原入口，由系统适配读取。已有对话尚未建立员工记录时，可保留其专业项目上下文并新建自己的资料区，不能把项目已有历史当成要搬迁的员工文件。

## 选择位置

优先沿用户指定位置或项目已有布局。没有约定时，可以在原项目的`employees/<稳定员工标识>/`建立资料区；使用稳定岗位标识或真实对话ID，名字变化不必移动目录。建立前查原入口与记录，已有同岗资料区就沿用，目标不为空或已有同名文件时不覆盖。

员工资料区是自己的责任、判断、经验和产物入口，不是必须新增的Git仓库、worktree、模型服务或执行环境。原Codex对话与项目cwd保持；代码、共享业务表、正式项目资料可以继续共用，引用原位置，不复制第二份真源。共享目录的修改仍按原维护责任协商。

默认布局如下，标明按需的内容不在建岗时强制生成：

```text
员工资料区/
├── AGENTS.md              短工作入口与目录约定
├── ROLE.md                岗位目的、职责、关系、授权及长期例外
├── STATE.json             最小身份、读取位置和实际回执指针
├── JOURNAL.md             岗位级重要变化，按时间追加
├── workbook/              有真实工作才逐件建笔记
├── CURRENT.md             有真实笔记后由已有生成器产生
├── experience/            有经验需要保留时再建立索引与案例
└── artifacts/             按需保存本岗产物；共享正式成果仍可在原项目
```

## 模板与唯一维护位置

| 输出位置 | 模板／产生方式 | 唯一维护的内容 |
|---|---|---|
| AGENTS.md | [入口模板](../templates/new-employee/AGENTS.template.md) | 共同Skill、ROLE、当前工作及运行记录的阅读顺序，目录边界；不复制岗位正文、任务表或默认模式 |
| ROLE.md | [岗位模板](../templates/new-employee/ROLE.template.md) | 员工称呼、岗位目的、职责和授权来源、关系与回报去向、共享真源、明确的长期约定与生命周期；不维护逐件进展和运行状态 |
| STATE.json | [最小运行引用模板](../templates/new-employee/STATE.template.json) | schema_version；identity中的thread_id、project_root；channels中的已核身份依据指针；source_checkpoints中的原读取记录指针；receipts中的系统接入与交付回执指针 |
| JOURNAL.md | [岗位日志模板](../templates/new-employee/JOURNAL.template.md) | 岗位变化的时间、变化、原因、来源和关联入口；单件工作的详细过程留原笔记 |
| workbook/实际事项.md | [逐件模板](../templates/new-employee/work-item.template.md) | 原有八字段及过程，见[工作本](workbook.md)；不从模板生成虚构承诺或假完成 |
| CURRENT.md | 原`scripts/workbook.py`或已有汇总器 | 只从笔记派生，不手工维护另一份进度。尚无真实笔记时可暂不存在，从ROLE理解待明确职责 |
| experience/index.md | [索引模板](../templates/new-employee/experience-index.template.md)，按需使用 | 问题→经验条目与范围、验证程度；不重复业务状态 |
| experience/实际案例.md | [经验模板](../templates/new-employee/experience-case.template.md)，按需使用 | 情境、观察、处理、反馈、结果、适用条件/反例与后续采用；业务事实链接原笔记 |

表中的STATE结构是新员工的轻量默认，不是现有员工JSON的迁移schema。渠道若尚未核实就保持空，不填示例账号；回执未取得就保持空，不填写虚假的ACTIVE或verified。读取工具已有独立游标文件时仅引用其位置，不在STATE复制第二个可修改游标。系统注册与调度配置由系统维护，STATE只存原回执定位，不抄任务prompt、监听器配置、事件账本或同一套技术状态。

需要继续保存的本岗真实原件/回执在原位置保留，证据目录按实际产生，不为了模板完整复制历史。RELATIONSHIPS.md只有关系复杂且ROLE不适合容纳时再独立，ROLE改为链接，不并排维护两份关系。共同模式、发送方法与系统接入方法仍引用Skill，不抄整套说明。

## 使用模板

从当前真实对话和原授权填模板变量；变量不是给用户的新表单。未知职责可标暂定/待明确，真实thread_id与项目路径从实际上下文核对，不用虚构ID。JSON用正确序列化保存，不能把引号、换行等值直接拼进JSON字符串。

先确认目标是新的员工资料区，再逐个生成必要文件及workbook目录；不直接把整个模板目录复制成一个带样例待办的员工。AGENTS、ROLE、STATE、JOURNAL可作为起步四文件；经验、成果目录及第一篇工作笔记按真实需要建立。字段模板的说明文字须替换为实际内容，未用模板不放进活动workbook。第一件真实承诺通常就是已授权接入或已交办工作，记录后调用已有生成器创建CURRENT并check；不伪造工作凑总览。

AGENTS只是这个资料区的入口。执行cwd不在此目录时，须把它作为稳定工作入口明确读入，并交统一系统用于后续接续；不能仅凭文件存在就宣称每次已自动加载，也不要为此给共用项目根新增会影响其他员工的岗位指令。

建立文件不等于员工上线。按[系统登记](system-onboarding.md)自动交现有责任方接通小时与已授权群@，分别取得配置和真实运行证据；员工不搭自己的监听器，不新增模型服务。
