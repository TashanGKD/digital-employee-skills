# 2026-11-20 共同方法归并

本次沿原digital-employee安装更新，依据本人已明确的11月16日AUP体系与任务闭环要求，以及随后关于员工自行推进、按原责任协作和真实交付的修订；不是从一次故障另选新方法。

- 统一AUP小号读、发、原生@来源；Mac作大脑、工作区与编排。Mac优先的旧方案只保历史及必要独立补读。
- 正式承接的任务，无论由本人派发、群内交办或职责内发现后承担，都继续到可用答复/产物、实际交付、工作本更新和关闭，或有责任人与恢复条件的真实等待。没有任务可以等待，不凭空找事。
- 六种工作方式与五种任务进度分开，保持原八字段、工作本生成器、旧笔记及历史。明确暂停不擅自恢复。
- SDK同一原ID追最终执行和原生回执；官方界面补交保准确原生证明与旧失败，unknown不换ID重发。发出、已读、采纳分列。
- 来源可读、事件入账、队列接受、原岗位实际开始工作及业务出站分层验。冷对话只排队不算已唤醒；重启恢复保旧队列及去重，方法文本不替代程序验收。
- 保留已有的自然交流、完整背景交办、自己排障、原协作者主责和使用效果核验。历史案例不抄成全员任务，也不从一条分支指令扩成父岗或全组织规则。

主入口、当前微信规范、岗位机制、工作本、交付/接续/验收、心跳与新员工模板一并对齐。没有更改业务、账号权限、运行器、员工暂停、既有自动任务提示词或专业Skill。新母版不意味着已保存的任务提示词自动改了；同机文件安装、独立宿主同步、员工实际读取和后来任务效果分别记录。

根目录RELEASE.json记本版逐文件哈希与版本，包含检查器及其负例测试。发布使用`scripts/check_method.py --package /绝对路径/新包.zip`，先跑负例和当前文档/清单校验，再创建新包，不覆盖已有文件。无参数仅帮助；检查不联网、不发消息，不是员工行为或全系统健康的保证。
