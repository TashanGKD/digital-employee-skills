# 运行环境接入：方法、接口和部署分开

本包提供工作方法、模板、工作本工具、受控队列整理库和隔离记事本客户端；不附带微信账号、微信SDK实现、解密器、原生@采集器、后台worker或完整记事本服务。不能把安装Skill说成渠道已经接通。

参考架构是AUP上的已授权微信账号负责读、发与原生@来源，Mac上的Codex负责员工判断、工作区和编排。AUP是参考部署的Linux工作站名称，不是通用产品或必须购买的服务。其他环境须重新确认工具与部署，不能继承原作者授权。

## 部署时确认的入口

| 能力 | 需要真实提供的东西 | 验收 |
|---|---|---|
| Codex协作 | 已有目标对话、官方队列工具、读取原生回合的工具 | 只入队、不打断，随后核原消息与实际接手 |
| 微信读取 | 已授权账号、会话目录、正文/附件接口、范围和覆盖收据 | 账号/peer/稳定ID/发送人/时间/缺口均可核 |
| 微信发送 | 已有SDK或授权官方客户端、唯一操作协调、原生记录读取 | 同请求核最终原生回执，unknown只查原单 |
| 消息唤醒 | 原生事件源、持久事件账本、准确账号/peer→员工路由、宿主队列入口 | 首帧、连续帧、逐来源覆盖、新鲜度和实际起回合分别核 |
| 调度 | 当前宿主公开支持的任务工具 | 查重、保存读回、首次自然运行分别核 |
| 共同记事本 | 当前服务契约、访问身份、必要记录字段、版本和幂等机制 | 保存后读回实际字段、历史及来源 |

把本部署的工具入口、实际账号、维护关系和原读位放在员工私有ROLE/STATE等原记录中。不要填进这个公开仓库，不把示例名当真实绑定。外部Skill（如飞书、邮件、会议工具）由宿主另行安装和授权。

## 默认行为

仓库检查只读本地文件；所有工具无参数只显示帮助或检查当前仓库，不自动发微信、启定时器或读取账号。已有授权内能自己处理的故障先排查并继续可做工作；涉及共享服务或凭据的变更协调实际维护者。明确被接口拒绝的权限不绕过。

## 接入结果分层

Skill可读取 → 工具已发现 → 配置保存 → 来源可读 → 事件入账 → 原队列受理 → 员工起回合 → 业务接住 → 实际产物 → 实际交付回执。

这些不是同一状态。对方已读、业务采纳也要另核。任何真实缺口保在原任务及下一条件里，不伪造消息、时间或回执让状态变绿。
