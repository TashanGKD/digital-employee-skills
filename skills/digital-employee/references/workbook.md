# 自己的逐件工作本

已有合适工作本就沿用并补缺口，不为使用Skill搬迁业务数据。以下默认结构只用于尚无合适接续方式的岗位：

- `employee/workbook/`：每个可独立交付或等待的结果一篇笔记。
- `employee/CURRENT.md`：从各篇当前摘要生成的工作总览，不手写第二份状态。
- 现有ROLE/STATE/JOURNAL、原件、回执和专业记录保留。STATE主要管渠道、读取位置、发送/运行状态及工作笔记指针；同一业务判断不要在两个地方分别维护。

关系含义以ROLE/现有关系说明为准，真实渠道/ID和读取事实仍在STATE。每轮在“怎么来的、这次想做到什么、下一步”交代谁提出、谁使用、回报谁、等谁；不为此增加一套业务表。

共用收件时，“怎么来的”保留实际点名/归属依据和原消息定位；职责交叉时在原字段说明本轮主责、协作者及已有共同行动/分派记录。自己负责的部分与别人承担的部分分别清楚，重复收件、补充和改派接回原项，不为每次被提名再建一件事。

## 事情怎样划分

一次原委托的结果为一个单位。内部步骤、同轮补材料、派工和沟通追加原笔记；本轮结果交付后关闭，独立下一轮关联接出；原来理解错了就纠正原项并留原因，不造一项假任务。科研按问题/独立研究交付组织，不把每条轨迹、每个工具调用写成待办。共同业务本、实验数据与问题树仍在原真源。

主动发现的有价值工作、暂留线索和候选想法也可记；记录不自动变承诺。等待要说明等谁的什么或哪个条件；暂缓要保留再次值得看的条件。不要因为空闲每小时催同一个人或重试同一故障。

候选事项在原“怎么来的”字段明确写“主动发现，尚未承接”及依据；已在授权职责内决定承担或后来实际接受交办时，在原项说明来源与转换原因。事情的承接性质和进度状态分开，“待推进”本身不能证明已经接受交办。无需增加监控字段或另建候选表，系统读取原文判断；依据不足显示未知。

## 当前摘要与过程

默认笔记的当前摘要采用八个自然字段；一行一个字段，复杂解释放后面的过程。用户有现成不同结构时保留它，适配自己的汇总方式，不强行套此模板。

```markdown
<!-- employee-work:start -->
# 本轮独立结果的自然名称

- **事情**：本轮独立结果的自然名称
- **怎么来的**：真实交办或主动发现的来源、时间及必要定位。
- **这次想做到什么**：这一轮怎样才算给人交代了结果。
- **我的想法**：当前理解、取舍或关键疑点；不把推断写成事实。
- **现在怎么样**：待推进
- **下一步**：目前自己能做的一步，或等待谁的什么。
- **时间**：明确截止、计划、复看时机或恢复条件；没有就说明，不编造。
- **过程笔记**：最近一次有意义变化和来源；原件/回执链接在原位置。
<!-- employee-work:end -->

## 过程

按实际变化追加，不抹去旧经历。事实更正写明旧理解为何改变。
```

任务进度：待推进、等反馈、先放放、已办好、不做了。

保留这五种进度及原生成器，不用“主动推进、等待来源/条件”等六种工作方式替换它们；工作方式见[岗位工作机制](operating-model.md)。已办好只指本轮独立结果，不等于整个项目落地。交办排队、产物收回、实际已发和业务采纳分别说明。

每件已承接任务在原八字段和过程里能够找到：原始来源定位、本轮目标及当前理解、已做动作、实际产物或答复、发送/交付回执、仍欠部分、下一步责任人和等待条件、当前进度。沿现有结构表达，不新增必填表、任务库或监控字段。没有外发要求的工作按原可检查产物/答复关闭，不为凑回执制造发送；有外发要求时不能用草稿或排队关闭。

确实受阻才转等待：先自行核入口、排障和合法备用，写清缺什么、谁处理、自己还可推进什么以及复看条件。一个工具故障不能冻结其他已承接任务；只留下“有缺口”不能算把事办完。明确暂停或取消保其来源，不能因持续责任私自恢复。

“这次想做到什么”写可观察的完成条件，沿原委托约定需要的内容、对象、载体、交付及质量范围；“过程笔记”链接实际产物与回执。探索工作可交代减少哪项不确定性，不预设必须得到正结论。缺项、未验证或只完成一部分时据实说明，不另建一份验收业务账本。共同标准见[验收依据](acceptance.md)，由系统复核真实情况，而非让员工每天填检查表。

## 何时使用

承接新工作时先用最少摘要记下来源、这轮要交什么、当前判断和下一步，并刷新当前总览，再深入制作。先有可恢复的责任，不必先写长过程；必要短回应与准备可自然交错。两件可独立交付的真实请求分别接续；内部工具步骤不拆成一堆任务。长工作在有意义的阶段保存产物入口、尚欠什么和恢复位置，避免工具已大量产出，工作本仍只显示旧的“等反馈”。

开工先看CURRENT，知道还欠什么、现在能推进什么和真正要等什么，再读相关笔记与新增讨论。实际交办、收到成果、交付、反馈或判断改变时，改原笔记当前摘要并追加过程，再刷新总页。一个工具卡住时，仍从本子选择其他已授权可做工作；没有有价值行动时安静等待，不制造任务。

从总览选择工作仍要判断：什么结果此刻最有用，是否有外部期限、上下游依赖和合适资源，是否已经有人承担。相关问题可在本岗位原授权内跨笔记关联，不每次从最新消息重新起题。计划安排、别人给的截止、等待条件与实验观察时长分别说明，不为排优先级编时间，也不额外建立固定打分系统。

新事实到来，先判断它使哪些旧前提、等待或下一步失效，再更新受影响的当前字段和直接关联项；不只在过程末尾追加一句。涉及目标、阶段或依赖变化时，复看整篇当前摘要，避免“下一步已获批准、时间仍等批准”等相互矛盾。无需每次小进展重审全部工作本。

已交付旧阶段保留其结果，并链接后续承接；变化中的等待条件主要留在活跃项，不在多个旧项复制。不同事项可有不同完成状态，例如试用已完成而周期工作未交付；不能改变原目标，把另一件成功的事当作本件完成。结构一致检查不能代替这项业务判断，具体更新工具沿本岗现有入口，不要求全员安装同一套编辑器或增加字段。

汇总脚本是本Skill的 `scripts/workbook.py`，Python标准库，无默认目标，无参数只帮助。以仓库根目录为例：

```sh
python3 ../scripts/workbook.py refresh --root /本岗位绝对路径/employee --execute
python3 ../scripts/workbook.py check --root /本岗位绝对路径/employee
```

脚本按笔记生成CURRENT；不编辑笔记、STATE、回执或共享账本。已有CURRENT不带本脚本生成标记时拒绝覆盖，先保留原文件并适配。脚本拒绝缺字段、未知状态、同名结果及符号链接，检测读取期间的来源变化。`refresh`没有`--execute`只预览是否一致。

自动汇总指工作流程在笔记变化后调用生成器，无须人或AI手写第二份表；不新增文件监听器或定时器。检查只证结构和总页一致，不能证明资料已读全、语义判断正确或用户已认可。

## 从现有文件升级

先核本岗位已做工作、交付回执和未完承诺，备份将修改的现有文件并保留原历史。不要清空STATE、重建消息ID、重置读取位置或将已交付改回待发。把现有承诺逐项对应原笔记或新笔记，保留证据路径；当前业务判断转为笔记维护，STATE留清楚指针与历史/运行事实说明。

现有JOURNAL继续追加岗位级变化，逐件过程放对应笔记；原JOURNAL内容不删。旧commitments/next_actions允许按事实纠正和改为当前笔记指针，但先保存旧快照及说明，不能把“保留历史”理解成永远并列过时状态。
