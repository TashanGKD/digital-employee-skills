# 事项判断与合成示例

以下均为说明方法的合成情境，不是原用户业务或真实回执。

| 区分 | 记录方式 |
|---|---|
| 本轮独立结果 / 长期项目 | 交一版方案完成，只关闭这一轮；后续执行另核 |
| 同轮补充 / 新一轮交付 | 未交前补师资依据进原项；交后明确返修形成关联新结果 |
| 已收材料 / 已付款 | 附件收到有据，款到账仍须独立证据 |
| 提出意向 / 实际接单 | 没有明确承接不写负责人已接受 |
| 真实截止 / 个人计划 / 复看 | 分别存，不凭过期推完成或全部改排今天 |
| 微信已发 / 已读 / 采纳 | 各核对应事实，技术送达不替业务接受 |
| 原记录成功 / 新报告 | 汇总复用原事实，不再计一次完成成果 |
| 主动候选 / 已承接任务 | 候选先保判断，正式承接才负闭环责任 |

## 当前信息与历史

新增事实后核“原结果实现了吗、哪句旧描述失效、现在还剩什么”。有证据变化时同步当前摘要、时间、状态或条件，并保原值、批注、来源和原因；只有纯备注不机械改全部字段。用户更晚暂停覆盖此前批准，但已发结果保留；不用旧催办重开已关闭事项。

关联只用于已有真实关系，不根据标题近似混项。技术来源修正不冒充业务进展，责任不明保待定。仅用已读资料复核时不取新源、不推进源检查点。

## 已发生的工作

已有事项追加真实进展；未预列但确已发生的独立结果可直接补记工作事实，不编造它曾经待办。记录实际发生时间及精度、执行或参与者、结果程度、来源及必要关联。消息到达时间、整理时间和实际业务时间不混用；未知不填今天。

按日周月查询同一事项及其进展，不另维护三套事实账。字段和可用操作以实际主库合同为准，不把本文件的语义说明当某服务必有的API。
