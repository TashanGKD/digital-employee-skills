# 共同记事本维护

先接续已有主库、原检查点和未完轮次，不建竞争账本。此岗位也采用[digital-employee](../digital-employee/SKILL.md)，自己的工作本保存本岗责任，组织记事本保存跨岗业务事实。Skill不赋予账号/主库权限，不继承原作者个人背景。

## 从原来源到实际记录

1. **恢复范围。** 从原工作入口、运行收据、来源终点和成功前缀理解未完；只读本轮已授权范围，见[来源](references/sources.md)。取得、正文读完、媒体已读和已经应用分别记录。
2. **读完整讨论。** 分批核正文、引用、语音和影响分工/时间/交付的附件。标题、机器转写和API接受不代替实际阅读；单源失败继续其他源并保缺口，不把失败记零新增。
3. **查旧项与新结果。** 同轮补材料、催促和约定变化进原项；独立新结果去重后关联新建。核旧摘要、时间、状态和等待条件是否已被新事实改变，纠正当前描述并保旧原话和批注。
4. **保存事实与不确定。** 接单、计划、排队和接口成功不是业务完成；用户明确已完成或不用管了不被旧催办重开。未预列但已发生的独立结果可补记工作事实，不虚构历史待办。规则见[判断示例](references/decisions.md)。
5. **保存并独立读回。** 按实际主库合同使用稳定请求号、真实ID、当前版本和必要来源定位；冲突重读最新用户输入后重判，不仅换版本强推。原生回执、历史与人工批注保留。见[记事本接入](references/local-api.md)。
6. **提交真实终点。** 只有已读、已应用并读回的范围推进相应检查点；不把一个来源成功当全源成功。恢复时复用原ID和成功前缀，不重建已存结果。

时间分清原要求、外部截止、个人计划、复看和条件；未知不塞今天，过期不自动完成。日周月从同一事项及其进展汇总，保可展开依据，不维护三套账，不给每次保存再记一次“成果”。

## 角色与触发

来源读取按现行部署路由，本包参考AUP统一微信源；必要Mac补读另标来源。飞书、邮件和会议等工具由宿主另行提供。原始记录、私聊、完整转写和媒体保持私有，只保存主库确有必要的摘要与定位。

按用户实际的定时/手动/暂停约定执行，不恢复原作者某个定时器。本轮有界结束，不自动另排下一轮，不发群、不派工、不因记事本里出现候选而代执行业务。须请用户决定时走其已指定渠道并核真实交付。

[背景模板](references/user-context.md)仅说明部署方应在私有处保存什么，不含原用户资料。仅用已读材料复核的任务不重新采集来源或推进检查点。
